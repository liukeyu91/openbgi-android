# Android 0.10.1-preview：空条目与立绘路径优化

2026-11-13，versionCode 14，ARM64 / Android 9+。

## 空演示条目报错

0.10.0 的独立 `org.openbgi.uipreview` 曾为界面检查准备 `ui-fure`、`ui-kanojo` 两个目录。
它们只有名称、编码和零字节 system.arc，没有可执行的游戏资源。
当时仅检测启动文件是否存在，错误地让这两个演示目录显示为可启动游戏。
这是 UI 预览准备的疏漏，不能解释为已经内置两部完整游戏。

本版要求根目录至少存在一个非空的 system.arc 或 ipl._bp，空演示条目自然退出列表。
启动时再次验证，缺失时显示易懂提示；导入只有空启动文件的目录也会被拒绝。
不删除演示目录、已有导入目录或任何存档，也不重新导入用户游戏。
这只是必要的启动检查，不声称能够验证 ARC/脚本内容的完整性。

用户已经在独立 UI Preview 里正常导入游戏，因此同时提供该包名的原位升级 APK。
其密钥、包名与原 UI Preview 保持一致；正式包 org.openbgi.port 另行提供。
两者的数据空间不同，安装正式包不会自动搬迁 Preview 中的游戏。
请对正在使用的包覆盖安装，不要卸载来升级。

## 有立绘时点击延迟

用户报告《与她》有立绘时推进对白约延迟 0.3 秒，CG/无立绘时正常。
用户选择先从源码排查、暂不操作手机，因此本版没有复现特定延迟现场、采集手机性能或替用户推进剧情。
不能宣称已确认该 0.3 秒的全部根因或已经消除延迟。

修改的是三条有明确计算开销的通用路径：

- ARGB → RGB 透明合成改为打包通道运算，保持原 7 位权重和目的高字节。
- 立绘变换的双线性采样同时计算四个通道，保留先水平再垂直的两次取整，边界仍按旧规则处理。
- Android 等尺寸画布拷贝预先裁剪源列，按行转换像素，绕开逐像素缩放除法。真正缩放仍走原路径。

没有降低分辨率、关闭平滑、简化透明度、调整游戏脚本等待或修改游戏文件。

## 验证与边界

- 原有 blit 回归通过；新增 129 万组打包合成对照与 9216 个单像素平滑采样/边界对照。
- 与冻结的 0.10.0 源码比较：257 个透明度级别、3000 个缩放/旋转/复制整缓冲对照一致，包含填充区。
- Android 画布与旧实现对比 30000 组：等尺寸/缩放、负坐标、裁剪、16/32 位、未对齐源行、缓冲哨兵及脏区一致。
- 完整目录导入回归通过，新增拒绝零字节启动文件与隐藏空演示目录的检查。
- NDK、Java、资源、DEX 构建，签名及 16 KB 对齐检查通过；包内无游戏和个人存档。

桌面 x86_64 / WSL / GCC -O2 合成基准的一次结果如下，仅用于确认代码路径提速：

| 合成路径 | 修改前 | 修改后 |
| --- | ---: | ---: |
| 640×720 立绘变换，最近邻 | 3.177 ms | 2.210 ms |
| 同尺寸，双线性平滑 | 12.916 ms | 11.669 ms |
| 1280×720 透明合成 | 6.686 ms | 3.812 ms |

以上不是小米 8 的帧时间，不等于游戏推进延迟。手机改善幅度、真实立绘/CG切换、画面和存读档由用户复测。
源码与修改前的离线比较材料、日志位于本地 work/runtime/perf-0.10.1/。
当前不操作手机，不自动覆盖应用，避免中断用户游玩。

## 源码与分发

标准 APK：org.openbgi.port；兼容升级 APK：org.openbgi.uipreview。
后者可用 tools/android/package-ui-preview.sh 构建，不生成演示游戏目录，也不包含测试钩子。
仍使用各自本地开发签名，密钥不在源码包中。
累计补丁基于 e347b36，包含之前版本的更改。没有向 GitHub 推送本轮修改。
