# 0.9.0-preview：手动重读输入框初始文字

本文件记录 ADB 恢复前的 0.9.0；后续见 [0.9.1 真机记录](android-device-validation-0.9.1.md)。

日期：2026-11-13。versionCode 11。本轮没有 ADB；没有安装或操作手机。
0.8.0 保持已测基线，预览版提供可复核的源码和 APK，不计作真机兼容通过。

## 行为

部分汉化作品的正文用 GBK，默认姓名仍保留 CP932 字节。
预览版在单栏 OS_Edit 和单/双栏、姓名生日原生表单中提供手动入口：
长按输入框，在 Android 选择/插入菜单中选择“初始文字乱码？”。
对照 SJIS、GBK、UTF-8 的原始初值，选择可读的一项。
选择仅替换当前栏，后续仍按游戏当前编码提交；不会模拟 Enter，也不会修改每游戏编码设置。
表单内其他栏分别处理，正常的确认/取消流程继续适用。数字栏和纯 ASCII 初值不提供该入口。

修复使用最初收到的字节快照，不从已经乱码的 Unicode 字符串反推。
快照独立复制；选择前不改文字或原字节。无法完整解码、目标编码无法表示、
超出字节上限或不符合现有字符过滤规则时拒绝替换，不静默丢字或写入问号。
例如 CP932 初值“青葉”可明确按 SJIS 解读，再编码为 GBK，交给现有游戏输入流程。

脚本更新/隐藏/销毁单栏控件后关闭旧预览；选择时再次检查快照、修订号、当前文字与输入限制。
表单还检查父对话框是否仍显示。后台、音频中断和 Activity 销毁时清理预览窗口。
这些 UI 防护已经实现并完成编译，但其实际设备行为尚未验证。
此功能不修改菜单资源，不批量转码旧存档，也不自动判断每个字段的来源编码。

## 本机验证

- 29 项新转换模型检查通过：CP932 初值转 GBK、原始字节不变、防御性复制、
  超长拒绝、无损编码、GBK/UTF-8/补充平面字符、ASCII 限制、控制字符、无效字节、
  空初值、未知选项，以及预览省略不截断真实候选。
- 原有输入过滤 10 项和编码抽样 39 项再次通过。
- 输入/按键 48 项与 270 组 Java/C 缩放对照再次通过。
- Android Java/D8 编译、APK v3 签名与 16KiB 对齐检查通过。
- 原生库与已测 0.8.0 APK 内的 libopenbgi.so 逐字节一致；本轮仅新增 Java 行为。
- 0.8.0 原交付物的三项 SHA-256、源码 ZIP 和独立索引上的累计补丁 apply-check 已复核，保持不变。

复现：`sh tools/android/tests/run-text-repair-tests.sh`、
`sh tools/android/tests/run-encoding-tests.sh`、`sh tools/android/tests/run-input-tests.sh`。
JDK 8+；输入/缩放对照还需主机 C99 编译器。测试使用自有短句，不需要游戏。
本地日志：work/runtime/p1-text-repair-tests.log、p1-text-repair-input-regression.log、p1-text-repair-package.log。

## ADB 恢复后的必测项

- 小米系统是否保留自定义选择/插入菜单项，复制/粘贴是否正常。
- OS_Edit 默认姓名与单/双栏、四栏资料表单，分别检查正确重读、取消和重复重读。
- 无法表示/超长/无效候选保持原文字；修正不自动确认姓名，不影响其他字段。
- 输入法候选提交、打开/关闭预览后的键盘恢复、返回键和旋转。
- 预览期间脚本更新控件、关闭父表单、切后台或音频中断，旧选择不得回写。
- 两部游戏存档读回、实际姓名保存及冷启动恢复，核对存档备份。

没有这些实测结果前，不宣称默认姓名乱码已经在具体作品中修好。
主机完整套件旧基线仍是 17/19，bpc、win32wide 两项旧失败未在本轮处理。
