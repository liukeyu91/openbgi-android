# Android 0.8.0：编码抽样、对照预览和 UI 转换

日期：2026-11-12。本地测试版，versionCode 10，ARM64 / Android 9+。
设备：小米 8 / Android 10。本轮未推送 GitHub。

## 使用

游戏库选择游戏 → 游戏设置 → 抽样探测 / 三编码预览。
工具只读取游戏目录，不启动 VM，不改游戏、存档或编码设置。
三列展示同一原始文本按 SJIS、GBK、UTF-8 解码的结果；下拉框可切换样本。
建议基于抽样，用户对照可读内容选择，回到设置页点击保存才生效。
取消预览或选择后取消设置页，都保留原配置。
没有足够样本时提示手动选择，不静默回退成另一个编码。

这些是脚本中抽到的首批正文，不保证是游戏实际执行后的第一句。
若目录中的汉化资源封装在 EXE 内，需要先准备成引擎可读取的文件；抽样器不执行 EXE。
遇到未支持的旧场景格式、加密/PCK 或复杂覆盖顺序，也应人工核对。

## 实现边界

纯 Java 的独立只读抽样器识别 PackFile、BURIKO ARC20、DSC 和现代/无头 32 位场景容器。
DSC 和场景读取逻辑参考同仓库的 dsc.c、hash.c、scnfile.c，采用显式长度/偏移校验。
对同名资源优先使用游戏根目录的散装覆盖文件；保留原路径和大小写。
不读取 UserData、.openbgi 或 Backup，不跟随符号链接。
它只读场景字符串引用，排除源代码位置和磁盘路径等元数据；SJIS 的 0x5c 尾字节不会被当成路径误删。

资源上限：目录深度 8、文件 12000、档案 128、索引累计 16MiB、候选资源 8192、
最多尝试 128 个资源、单资源存储/解压结果各 4MiB、数据预算 32MiB、8 个场景/160 条样本。
达到上限会显示“有限抽样”。只建议，不自动应用；语言统计启发式仍可能误判。
工作线程可取消；关闭界面后不再更新旧对话框。
该解析器不调用原生游戏解码器，也不解析或执行脚本指令的行为。

## 明确修复的转换路径

此前 Android 标题和 OS_MessageBox 都调用固定 CP932 转换。
现在标题按游戏所选文本编码转换。
消息框正文使用 core/error.c 已有的 MsgBoxScript 来源标记（标题后缀 ` (script)`）选择脚本编码，
消息框标题和未标记的引擎内置提示仍走 CP932。
没有按“看起来像中文”猜测运行时字节，也没有更改文件名的 CP932 路径接口。
GBK 转换保留完整字符边界，零容量不写缓冲。

这解决了 GBK 标题/脚本消息框的一条确定性遗漏，不能等同于混合编码问题全部解决。
默认姓名、菜单以及同一作品中来自不同来源的字符串仍需继续追踪；本版不自动转码这些字段或旧存档。

## 已验证

- 39 项主机检查：三种编码、ASCII/短文本歧义、混合样本提示、无效字符、DSC/场景与 ARC 两种格式、
  散装覆盖优先、原文件未修改、截断/畸形/长度溢出、取消、存档目录排除等。
- 独立原生宿主 9 项通过：GBK/SJIS/UTF-8、补充平面字符、Euro、完整字符边界、短/零容量，
  以及 GBK 模式下 CP932 内置文字仍按 CP932 转换。
- 两个实际 Android 对话框分别显示 GBK 脚本正文“中文AB”与 CP932 内置正文“日本”；
  同一脚本消息框的 CP932 标题也正确，窗口标题日志正确显示中文。
- 两部手机汉化目录均建议 GBK，显示可读开场文本；Kanojo Step 正确使用散装汉化覆盖而非原始档案。
- PC 只读扫描：Fureraba 汉化档案建议 GBK；Kanojo Step 未展开 EXE 汉化的原目录建议 SJIS。
  这是被读取资源不同导致的结果，不能把原档案建议等同于整个封装补丁的编码。
- 自有 SJIS/UTF-8 fixture 真机预览通过；选择 UTF-8 后取消仍为 SJIS，保存后变为 UTF-8。
- 空 fixture 提示手动选择；三个样本切换、真实 GBK 配置保存和选择后取消保留原配置均通过。
- Java/原生编译、APK 签名/对齐；产物审计及累计补丁 apply-check。

本地主证据：work/runtime/p1-encoding-tests.log、encoding-native-tests.txt、encoding-ui-validation.json、
encoding-*-preview*.xml/png、encoding-baseline/。
真实游戏样本和存档备份不进入公共源码；测试源码使用自有短句生成 fixture。
