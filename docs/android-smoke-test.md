# Android 1.0.1-android 真机冒烟

准备两台 Android 11 或更新的 ARM64 设备，其中一台用低配机。全功能包用原目录运行，SAF 包用系统选择器复制导入。游戏库和存档按包独立。

| 游戏 | 检查点 | 设备 A（全功能包） | 设备 B（SAF 包） |
| --- | --- | --- | --- |
| Making＊Lovers HD 汉化版 | 标题页、开场影片、声音、首个可操作场景 | 待测 | 待测 |
| KanojoStep 汉化版 | GBK 对话、回看、存档后退出并重进读档 | 待测 | 待测 |
| LoveHp（1.680 样本） | 简中／繁中／英文资源切换、Big5 字形、场景模糊 | 待测 | 待测 |

每个游戏先确认可导入、可启动，再走表中检查点。全功能包检查原目录中的存档和资源是否保持原样。SAF 包确认安装后可直接进入系统选择器。

## 回传模板

```text
设备型号 / Android 版本：
OpenBGI 版本 / 安装包类型：
游戏 / 游戏版本 / 补丁：
最后到达的位置：
结果（通过 / 失败 / 未测）：
复现步骤或卡住的位置：
日志 ZIP：
```

测试或复现后，回到游戏库，从“关于”导出运行日志，再打开下一款游戏。ZIP 中的 `run-report.txt` 汇总构建基线、设备、运行用的引擎和编码、补丁指纹、最近执行的 VM 程序和错误。场景名称可手填。补丁指纹来自已安装的覆盖包或解包记录，手工替换的原目录资源可能没有指纹。

验收需收齐两台设备的实测报告。表格里的“待测”随实际结果更新。

主机回归已用上游 v1.0 的补丁加载路径验证 ZIP 双向互通，覆盖子目录、CP932 文件名和原资源回退。
