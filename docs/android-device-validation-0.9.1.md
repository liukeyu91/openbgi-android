# Android 0.9.1-preview：输入框真机回归

日期：2026-11-13。ARM64，versionCode 12。设备：小米 8 / Android 10 / Adreno 630。
从 0.8.0 经 0.9.0-preview 到同签名 0.9.1-preview 覆盖安装；未卸载主应用。

## 本轮修复

- 0.9.0 仅依赖系统浮动文字工具条；本机无法稳定显示自定义项。
  非 ASCII 初值的输入框现在长按打开明确的“输入框操作”，选择“初始文字乱码？”。
  同一操作框提供全选、复制、剪切、粘贴，并保留系统文字选择入口。
  标准操作交给 EditText 处理，继续遵守原有编码、长度与字符过滤。
- 单栏输入框的物理 Enter/Tab 现在消费按下和抬起，只在抬起时确认。
  旧实现可能先在按下时触发 TextView 的 editor action，抬起时又确认一次。
  连续输入框测试最初因此失败；修复后下一栏不会被上一栏的 Enter 提前提交。
  软件输入法的完成动作继续使用 editor action。
- 预览不再强制隐藏输入法。没有改动游戏字体、对话框坐标或画布缩放。

原始初值仍保留独立字节快照，候选使用严格解码/编码；只替换当前栏，
不切换整部游戏编码、不模拟确认、不转换已有存档或游戏资源。

## 验证

- 转换模型 29 项、旧输入过滤 10 项、编码抽样 39 项通过。
- Java/D8、APK v3 签名和 16KiB 对齐检查通过。
- 主应用和宿主测试使用相同的 Java DEX。随后原生变更只涉及信号终止和日志上限，没有改动渲染/VM 执行路径。
- 覆盖安装后六个已有 .sud 的 SHA-256 与升级前逐一一致。
- 独立宿主实际调用 OS_Edit、OS_DialogInput1/2、OS_DialogProfile，使用自有初值而非游戏资源。
  六项姓名/表单回归与三项保护回归见下方最终结果。

## 崩溃记录修复

旧 native-crash.txt 为 1,373,735,904 字节，反复记录信号 11。
已完整 gzip 备份并验证解压 CRC，再清理手机旧文件；本地备份约 3.3 MB，不公开分发。
旧处理器在 SIGSEGV 测试中未按预期退出。[ART 信号链源码](https://android.googlesource.com/platform/art/+/master/sigchainlib/sigchain.cc)
标注 SA_RESETHAND 未实现，因此不再依赖该标志加 raise。
现在使用异步信号安全的 write 和 _exit，记录后结束独立引擎；
超过 64 KiB 的旧信号日志在引擎启动时清理，不在信号处理器里操作。

直接终止可避免循环，但被接管的这些 native 信号不保证产生系统 tombstone/完整回溯。
导出仍包含引擎日志、Java 异常、最小信号记录及系统可提供的退出信息；不承诺每次都有原生栈。
Android 11+ 退出信息和其他 ROM 仍待验证。

## 复现宿主检查

使用 `ANDROID_HOST_TEST=1 make android-native` 构建独立库，再运行
`sh tools/android/package-hosttest.sh` 打包 org.openbgi.hosttests。
主应用 APK 不含 Engine_Main 包装器；测试不用游戏、用户存档或公开测试入口。

在独立测试应用里准备一个含空 `ipl._bp` 的测试游戏并选择 GBK。
在该测试游戏根目录放空文件 `repair-only`，从启动器启动测试。

1. 单栏初值：打开预览并取消，确认不改字；重开后选择 SJIS，再正常 Done。
2. 第二个单栏：打开预览后 Home，返回确认旧预览关闭，再修正和 Done。
3. 单栏表单：修正后取消父表单，输出应保持 unchanged。
4. 单栏表单：修正后正常 OK，原生收到 GBK 青葉。
5. 双栏：只修正 Left，Right 的中文不变。
6. 四栏资料：依次按 SJIS 修正为青葉、太郎、花子、私，生日保持 2 月 3 日，正常 OK。

放入 `repair-guards-only` 则优先运行三个保护检查：
打开旧预览后在测试游戏根目录创建 `repair-update-go`，脚本会更新初值；
旧预览应关闭，新预览按 SJIS 修正为太郎后 Done。
接着验证 UTF-8 字节上限拒绝 SJIS 候选、GBK 拒绝 UTF-8 emoji 候选；
两项都取消预览，使用正常编辑操作输入 AB，再 Done。
日志需出现全部 HOSTTEST PASS 和 HOSTTEST ALL PASSED。

故意异常也只用于独立测试 APK：根目录 crash-segv 触发非法地址写入，crash-abrt 调用 abort，优先于其他模式。
此类首帧前退出的测试不要用 am start -W 等待首帧。
用户 APK 不含 Engine_Main 包装器或这些故意异常入口。

## 范围与待办

- 本机截图中，预览返回后输入法首帧仍偶有白底/局部未重绘，触摸后重绘；
  现有调整未消除，已撤回无效的全屏焦点调整，不将此项记为通过。
  尚需区分测试窗口、输入法和实际游戏中的表现，并验证更多输入法/设备。
- 实际改姓/备注入口局部黑屏未修；本轮没有通过姓名持久化/备注保存。菜单混合编码和全流程仍待处理。
- 实体手柄/鼠标、真实来电/耳机拔出、其他 Android/GPU 仍待测。
- 主机完整旧基线仍为 17/19；bpc、win32wide 两项旧失败没有在此轮修复。
- 签名仍为开发测试签名；正式 key 和完整存档迁移属 P2。
- code 12 高于 0.8 的 10；普通覆盖不能降回较低 code，不能靠卸载回退，否则内部数据会丢失。

本地证据保存在 work/runtime/device-0.9-validation，包含升级前存档配置 tar、
六个存档校验、宿主日志和截图；不随公开源码打包。
