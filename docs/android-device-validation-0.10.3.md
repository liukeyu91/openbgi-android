# 0.10.3-preview 真机优化验证

2026-11-13，小米 8 / Android 10 / Adreno 630。用户授权继续优化并允许较积极的实现修改。
测试前已备份两个应用全部存档和每游戏配置；测试操作为原位安装、现有快速读档、少量对白推进和独立原生测试程序。

## 无钩子安装包的实际推进

沿用 0.10.1/0.10.2 的方法：冷启动，读取相同 Kanojo Step 快速存档，
停在祖母房间、乃绘「诚如您所言。这批榻榻米是去年才更换的……」这句。
截图确认就绪后注入三次原地 100 ms 触摸，间隔约 2.5 秒。
InputDispatcher 的抬手派发时间经 atrace realtime_ts 对齐带毫秒墙钟的录屏，读取下一句首次可见帧。
约有一至两帧加输入交付误差，录屏也会影响负载；这是单片段的前后对照。

| 推进 | 0.10.1 / 14 | 0.10.2 / 15 | 0.10.3 / 16 |
| --- | ---: | ---: | ---: |
| 主角「哦，刚刚口吻……」 | 103 ms | 86 ms | 85 ms |
| 立绘变化后乃绘「是吗？谢谢您的赞誉……」 | 1112 ms | 908 ms | 669 ms |
| 主角旁白「从刚才的对话来看……」 | 104 ms | 86 ms | 69 ms |

本轮立绘切换约减少 239 ms、26%；相对 0.10.1 约减少 40%。普通换句的十几毫秒变化处于测量波动范围。
剩余等待仍包含首次解码、内部图层构建和游戏演出，不能宣称所有有立绘场景都已消除延迟。
本地证据：work/runtime/perf-0.10.1/device/timed-aggressive-release.mp4、-trace.txt、-timing.png；
原对照为 timed-cache-release.* 和 timed-updated-play.*。这些文件及游戏截图不随公共源码分发。

## 分段计时定位

临时 APK 仅为测量链接包装函数；最终交付 APK 不含计时/校验钩子。
下表为同一片段的阶段样本，多个阶段有包含关系，不能把各行相加。编译器均为 NDK Clang -O2。

| 指标 | 0.10.2 参考样本 | 本轮组合候选样本 |
| --- | ---: | ---: |
| 实际图片解码次数 | 7 | 7 |
| 图片解码总耗时 | 203.052 ms | 106.502 ms |
| 文件打开命中及未命中总耗时，含路径处理 | 54.479 ms | 3.377 ms |
| LoadFile 总耗时，包含解码等 | 279.358 ms | 151.938 ms |
| 单次交叉淡化的中位耗时 | 5.801 ms | 2.016 ms |

新旧采样中交叉淡化的帧数会变化，因此同时看单次耗时，不用总帧数推导动画时间。
Blit 的日志仅记录超过 1 ms 的调用，不能把这些样本的合计当作所有透明合成的完整成本。
CBG v1 图层的首次解码明显下降，CBG v2 身体图仍约 36–45 ms。资源查找优化减少了反复目录扫描，未改游戏的松散文件/档案优先顺序。
本地日志：work/runtime/perf-aggressive/first-three.log、neon-first-three.log、paths-first-three.log、final-first-three.log。

## 正确性检查

主机运行 cbgfast、cbgcache、codec、blitfast、blit、posixpaths 共 6 组相关回归，全部通过。
另外直接交叉编译 ARM64 原生程序，在同一手机上运行以下检查，全部通过，无须安装额外测试应用：

- CBG：4000 组预测还原/哨兵比较，覆盖 8/16/24/32 位、零/小尺寸和未对齐地址；1200 个 Huffman 流，包含超过 8 位的长码、单符号树及页保护后的最后字节。
- 合成：30 万组像素，4000 组交叉淡化缓冲、4000 组 alpha 缓冲、3000 组部分重叠缓冲；覆盖透明度边界、填充区、非标准比例、源目标别名和裁剪行。
- 路径：大小写、未命中、立即创建/删除/改名、切换工作目录、缓存淘汰、超预算目录及并发读取。测试只使用独立临时目录并在成功后清理。

临时校验 APK 额外链接冻结的 0.10.2 CBG 解码器，比较真实图层的新旧输出。
14 次逐字节对照全部一致，0 次不一致，包含 CBG v1/v2；原始日志为 work/runtime/perf-aggressive/verify-old-decoder.log。
该校验模式会额外执行旧解码器，不用于性能结论。
