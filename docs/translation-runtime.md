# 汉化运行时适配

Android 1.0 使用共享 JSON 声明资源机制、文字编码、引擎和字体要求。适配能力放在通用读取/渲染接口中，游戏配置只描述已知要求。

## 当前实现

- `PatchImport.Profile` 与配置生成器传递 `font_family`，不再丢弃这一字段。MakingHD EVB/CPK、KanojoStep 与 Friend to Lover 配置选择中文 Noto CJK。
- `GameSettings` 持久保存字体和已识别适配器；`TranslationRuntime` 从旧汉化处理记录迁移字体要求，不重置手动编码或引擎。用户恢复“跟随游戏”后不会在每次启动被重新覆盖。
- Java 在引擎启动前通过 JNI 传入 UTF-8 字体名；FreeType 后端替代脚本字体选择，保留原有字号、字宽、粗体和斜体规则。中文/日文 TTC 字体按实际 family 名查找，不依赖固定 face 序号，也不再把 UTF-8 汉化默认当作日文字体。
- `OS_FontAddFile` 和 `OS_FontAddMemory` 直接注册 FreeType 字体，支持无 fontconfig 的 Android。内存字体保留自有字节，原载荷释放后仍可绘制；不再写 `/tmp` 临时字体。字体查询与枚举包含注册字体；尺寸和渲染继续共用相同的 glyph 查找。
- 补丁处理记录每个生成资源的 SHA256。再次运行保留归属记录；更新包可替换与旧记录完全一致的文件。用户修改过的补译/覆盖资源保留；不同来源同名而内容不同仍按已有优先级配置解决，未明确时拒绝混用。
- 已知压缩载荷错误的修复、更新资源替换都保留失败回滚。存档不进入覆盖列表。诊断日志记录实际适配器和字体。

## 验证与实际范围

字体测试使用实际 FreeType 和 CP932/GBK/UTF-8 转换，比较像素与字宽；注册字体的文件、内存两种来源应绘制一致，且内存来源不借用调用者的原缓冲区。Java 测试覆盖共享配置生成、迁移、手动选择、官方更新、重复处理和手工补译保护。

这版实现了字体替代、字体注册和有归属记录的资源更新。现有字宽修复与资源解包继续复用。没有新增未经样本验证的字符映射表或 DLL 脚本逻辑改写，也没有执行 Windows DLL。任意新 DLL 的逻辑、路线和全流程仍需实际游戏验证。

原目录运行与复制导入共用此运行时适配流程。
