# 0.10.2-preview 分段计时与缓存验证

2026-11-13，小米 8 / Android 10 / Adreno 630。
用户继续授权手机测试，未修改游戏资源。操作范围为覆盖安装、现有快速读档、少量对白推进和后台恢复。

## 已确认的耗时

使用单独链接的临时计时 APK，包装 LoadFile、BGI_CbgDecode、OS_FileOpenRead、OS_FileRead、Compositor_Render、Blit 和 OsAndroid_Render。
计时钩子不进入交付 APK，不改脚本速度、图片内容或解码结果。使用系统启动时钟记起止，日志只留本地。
同一快速存档起点为祖母房间、乃绘「诚如您所言。这批榻榻米是去年才更换的……」。

第二次推进包含立绘变化，一次测量如下。分类间有包含关系，不能把表内耗时直接相加。

| 分类 | 0.10.1 | 0.10.2 |
| --- | ---: | ---: |
| 图片实际解码次数 | 14 | 7 |
| BGI_CbgDecode 总耗时 | 403.792 ms | 203.052 ms |
| LoadFile 总耗时，包含解码等 | 451.403 ms | 279.358 ms |
| OS_FileRead 大块读取总耗时 | 0.592 ms | 0.675 ms |
| 文件打开命中总耗时，包含路径处理 | 25.397 ms | 24.079 ms |
| 文件打开未命中总耗时，包含目录扫描 | 32.935 ms | 30.400 ms |
| Compositor_Render 各帧总耗时 | 160.330 ms | 169.585 ms |

同一组 7 个图层在一轮变化中被加载两遍。修复后第一遍按需解码，第二遍全部复用结果，每个 LoadFile 约 2.6–4.8 ms。
其中包含 CBG v1 的嘴/眼/表情/发型等大图，以及 CBG v2 的身体图，尺寸包括 1280×920、1280×2760。
该片段明显存在重复解码，不能像初次只看录屏时那样主要怀疑脚本演出。
另一方面首次解码、合成及资源查找仍有开销，剩余等待不能全部算作某一个环节。
实际读取已可能命中系统页缓存，该结果不代表所有设备和冷存储读取速度。

本地日志：work/runtime/perf-stages/first-three.log、cache-first-three.log；不放入公共源码。

## 无计时钩子的点击复测

沿用 0.10.1 的录屏方法：atrace InputDispatcher 的抬手派发时间，经 realtime_ts 对齐带毫秒墙钟的系统录屏，读取下一句首次可见帧。
每轮均冷启动、同一快速存档、三次原地 100 ms 触摸，输入之间约 2.5 秒。误差约一至两帧加输入交付时间，录屏会影响负载。

| 推进 | 0.10.1 / code 14 | 0.10.2 / code 15 |
| --- | ---: | ---: |
| 主角「哦，刚刚口吻……」 | 103 ms | 86 ms |
| 立绘变化后乃绘「是吗？谢谢您的赞誉……」 | 1112 ms | 908 ms |
| 主角旁白「从刚才的对话来看……」 | 104 ms | 86 ms |

普通换句的十几毫秒变化处于测量波动范围。立绘切换约减少 204 ms，与分段计时定位到的重复解码相符。
这是该片段的一次前后对照，不是全游戏延迟统计，不声称所有立绘卡顿都修好。
本地证据：work/runtime/perf-0.10.1/device/timed-updated-play.*、timed-cache-release.* 及对应 -trace.txt、-timing.png。

## 正确性与生命周期

- 新增真实 CBG 图像单元回归：8/24/32 位像素及尾部哨兵一致；同地址内容改变重新解码；坏校验数据不缓存；输入/输出由调用者释放或修改不污染缓存；清空/禁用、容量回退及 LRU 淘汰通过。
- 原 codec 回归（hash、DSC、CBG、ARC）通过。
- Android ARM64 native、Java/DEX、双包签名及 16 KiB 对齐检查通过。
- 临时校验版逐个把真实游戏图层的缓存结果与普通解码结果逐字节比较，包含 CBG v1/v2；14 次全部一致、0 次不一致，记录在本地 verify-real-images.log。
- 缓存预算最多 64 MiB/16 项，并在后台和引擎结束时清空；真实后台恢复未观察到崩溃，但既有的局部黑块仍有出现，不能将后台显示记为完全通过。
- 主应用/独立 UI Preview 最终安装标准 0.10.2 / code 15，移除临时计时/校验 APK，恢复 debug.openbgi.stageprobe 原值。
- 测试前备份，测试后主应用 10 个、UI Preview 1 个 .sud 的 SHA-256 均一致，没有增加或删除存档。
- 两个最终安装 APK 的 SHA-256 与 outputs 交付包一致；原生崩溃文件仍为空，无新增 Java 崩溃文件。最终结果见本地 work/runtime/perf-stages/final-verification.json。

仍待处理：首次解码速度、图层合成/交叉淡化、资源路径查找、既有局部黑块及更广的真实场景验证。
没有修改脚本等待、图像分辨率或游戏数据。游戏图片、存档和录屏仅保留本地，不随源码包或 APK 分发。
